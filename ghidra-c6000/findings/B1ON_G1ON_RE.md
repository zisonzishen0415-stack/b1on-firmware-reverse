# Zoom B1on/G1on 固件逆向发现(总览)

目标固件:ZOOM B1on v1.30 / G1on v1.21(Updater 内嵌 OS 镜像)。
两机 OS 镜像逐字节一致(11 条记录),差异仅在文件系统分区。

## 硬件与工具链

- DSP:TI C6000 家族 C64x+/C674x(小端)。
- 工具链:TI C6000 Code Generation Tools 8.x(`dis6x`/`cl6x`/`ofd6x`)。
- 代码地址空间:`0xC007_8D20` 起约 325KB 主代码,`0xC00C_8580` 起约 76KB,
  另有若干小代码块与 `0x1180_xxxx` 数据/状态区。

## 运行时 ABI(已验证)

- 入参寄存器:`A4, B4, A6, B6, A8, B8, A10, B10, A12, B12`
- 返回值:`A4`(64 位为 `A5:A4`)
- `B15` 栈指针(8 字节对齐,向低增长),`B14` 数据页指针,`B3` 返回地址
- 调用约定:`CALLP` 将返回地址写入显式寄存器(通常 B3 或 A3)
- 音频回调:每声道每回调 **8 个 float32 样本**(`LLLLLLLL RRRRRRRR`)

## 关键数据结构(反编译交叉验证)

### 效果槽注册表(`0xc003f200` 区)

反编译 `c008940c`(记录查找):

```c
int f_c008940c(int slot, int sub) {
    return *(int *)(slot * 0x1c + 0xf204) + sub * 0x30;
}
```

即:28 字节槽记录 + 48 字节子记录(与 28B/48B 记录格式一致)。

### 每槽处理器表(安装函数 `c00bea38` / `c00beac0`)

```c
*(undefined4 *)(iVar1 + 0xd528) = *(undefined4 *)(record + 8);  // 0x6840/0x6844
```

绝对地址 `0xc00dd528` 附近是每槽处理器指针表;默认处理器
`0xc00c6840 / 0xc00c6844`。

### 效果分发器(`c00bada8`)

```c
void f_c00bada8(int ctx, int param_2) {
    if (*(int *)(ctx + 2) != param_2) {
        if (*(code **)(ctx + 7) != 0) {   // 48B 记录 word7 = 处理器指针
            (**(code **)(ctx + 7))();     // 间接调用效果处理器
            return;
        }
        ...
    }
}
```

与手工分析一致:48 字节记录 `word7` 指向槽处理器,分发器经其间接调用。

### 槽激活链(`c0098784` → `c0098b98` 等)

反编译显示注册表写入形如:

```c
*(uint **)((int)slot * 0x2c + 0xb370) = param_3;
```

即按槽号 `*0x2c` 偏移写入 `0xb370` 基址附近的激活状态区。

### 三个未完全反编译的函数(内容与证据)

以下三个函数属于"效果槽生命周期管理",互为调用链:

**`c0098b98` — 槽激活入口(调度)**

- 反汇编证据:标准序言(`SUB B15,8,B15`、保存 B3、`MPYLI A0,A11,A1:A0`
  做槽号/参数运算、`MVK/MVKH` 构造 `0x1181xxxx` 状态区地址)。
- 主体调用记录查找助手:`c0089434` / `c008946c` / `c00895f4` /
  `c008940c`,并按返回值大量条件分支;还调用链上兄弟 `c0098994`
  与 `c00b4c24`。
- 推断:按参数(槽号等)查 28B/48B 记录,决定激活/去活路径。

**`c00989e4` — 效果预算检查**

- 部分反编译证据:`func_0xc00c7560()` 取上下文 → `(uVar1 & 1) == 0`
  标志位分支 → 栈上浮点累加。
- 函数体含 `ADDSP`/`CMPGTSP`(浮点比较),并**递归调用自身**
  (`CALLP 0xc00989e4`)。
- 与手工分析一致:读状态字段(手工标记 `w28`)与 210.0f 上限比较,
  逐槽累加效果预算。

**`c0098784` — 槽激活链主状态机**

- 已有 9.7KB 部分反编译(见 `examples/decompiled/fn_c0098784.c`)。
- 证据:写槽注册表 `slot*0x2c + 0xb370`;查 48B 记录
  (`c008946c` / `c00894d4`);效果类别(ID=4)走特殊安装路径;
  写 `0x8540` 基址配置表;检查 `0xb23c` 掩码位。
- 推断:槽挂入/摘出运行链的主状态机;调用的 `c008940c/c00894d4`
  即已成功反编译的记录查找函数。

> 这三个函数无法干净反编译的原因与内容无关,而是固件"代码区嵌数据表"
> 导致 Ghidra 流分析越界(详见 `KNOWN_LIMITATIONS.md`)。

## 状态区与预算

- 自定义效果固定 1KB/槽(地址 `0x11800000 + slot*0x400`)。
- 延迟/混响类使用外部 5×640KB 缓冲(`0xC01A5800 + slot*0xAC440`,
  表 `0xc00df948`)。
- 预算检查(`c00989e4`)读取 `w28`,上限 210.0f。

## 加载器与菜单

- Updater 内 FS 为 4096B 块(6 字节头 prev/next/size),文件表 32B/条。
- `FLST_SEQ.ZDT` 决定菜单可用的效果类别;类别 ID = `real_type`。
- B1on 菜单 96 项,G1on 105 项。

## 验证状态

- 全量反汇编:112,233 条指令与 `dis6x` 逐条对齐(含取指包头伪指令)。
- 关键函数反编译通过:记录查找、槽处理器表安装×2、分发器、槽激活链。
- 已知限制见 `KNOWN_LIMITATIONS.md`。
