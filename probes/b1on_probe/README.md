# B1on ctx[3] 只读探针（2026-08-15）

目标：一次性测出 B1on 给自定义 ZDL 分配的 ctx[3] 状态区大小，并找出
“哪个字段会让 B1on 分配大状态区”（w28？real_type？）。

## 原理

探针 DSP 只**读** `ctx[3][0..2]`（base/end/span），**从不写状态区**，
只在 `end-base >= 阈值` 时用声道 wobble（左右音量交替 0.08/1.80）报告成功；
否则直通。报告计数器写在已证明安全的 `ctx[2]+0x18`。

用法：音色链里放一个探针，把唯一旋钮 Arm 开到 1，听输出：

- 听到明显的左右交替 wobble = 该阈值被满足（ctx[3] 至少这么大）
- 无声/直通 = 阈值未满足（ctx[3] 更小，或 Arm=0）

## 判读表（刷完后对照）

> **2026-08-16 静态更新**：固件里已定位 5×640KB 外部延迟缓冲
> （0xC01A5800 + slot*0xAC440，表在 0xc00df948）。B 组探针是决定性
> 验证：若 B1dly704K wobble，说明 real_type=DLY 身份确实把 ctx[3]
> 指向这些大缓冲，自定义大状态模块按 DLY/REV 身份打包即可。

| 现象 | 结论 |
|---|---|
| A 组只有 0640/001K wobble，其余直通 | 自定义效果状态区 = 1KB，与崩溃阈值吻合 |
| B1dly704K wobble | real_type=DLY 触发大区 → 我们按 DLY 身份打包即可 |
| B1w1557MK wobble | w28 触发大区 → 改 w28 即可（按静态证据，预计不会发生） |
| 所有组都 wobble | B1on 其实给了大区，崩溃另有原因（需再查） |
| 探针加载即死机/无音 | 说明问题不在状态区写入本身，而在文件其它特征 |

注意：一次只刷一个探针；如果某探针导致卡引导，先用 ZEM 刷回原厂固件再继续。

## 元数据验证(2026-08-16)

scripts/check_probes.py 已核对全部 13 个探针:real_type(FLT=2/DLY=8)、fxid=0x01A1、bass_flags=0、sort_fx_type 匹配、SONAME 前缀(ZDL_FLT_/ZDL_DLY_)一致——可放心刷机。

## 单文件扫描探针(2026-08-16 新增,推荐)

`out/B1sweepFLT.ZDL` 与 `out/B1sweepDLY.ZDL` 把 13 个二分探针合并成
**一次刷机**测出精确 span:

1. 只刷其中一个,放进音色链,把 Arm 开关打到 1,从头听输出。
2. 每 1.5 秒自动切换一个阈值档位(共 12 档,18 秒);当前档位满足
   `end-base >= 阈值` 时输出左右 wobble,不满足则直通。
3. 数开头连续 wobble 的段数 N:

| N | span 下限 | N | span 下限 |
|---|---|---|---|
| 0 | < 640 B | 7 | 64 KB |
| 1 | 640 B | 8 | 128 KB |
| 2 | 1 KB | 9 | 256 KB |
| 3 | 2 KB | 10 | 512 KB |
| 4 | 4 KB | 11 | 704 KB(大区) |
| 5 | 8 KB | 12 | ≥ 704 KB |
| 6 | 16 KB | | |

判读:FLT 版预计 N=2(1KB 槽区);DLY 版若 N≥11 即实机确认
real_type=DLY 拿到 640KB 外部缓冲(大区)。

构建可复现:build_b1on_probes.py / build_sweep_probe.py 使用内嵌工具链
(repeat98_tmp/build),13 个旧探针重建后与原始文件 SHA-256 逐字节一致。
