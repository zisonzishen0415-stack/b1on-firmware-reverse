## 2. 新发现:Updater 实为 **18** 条 YSX 记录(上一轮文档只记了 11 条)

记录格式不变(`01 59 53 58` + 小端 addr + 小端 len + data),但 G1on v1.21
Updater 里有**两段连续记录链**:

- 链 A(11 条,exe@0x4AAA0 起):地址/长度与上一轮文档 11 条完全一致
  (0x1180F800/0x92A0 … 0xC00DEC6C/0x17EC),即共有的 OS 镜像。
- 链 B(7 条,exe@0x3D5838 起,紧邻一条链):**上一轮未记录**。

| 地址 | 长度 | 初步判读 |
|---|---|---|
| 0xC01C5800 | 0x1A300 | 更新模式代码/数据主体(107KB) |
| 0xC01F8178 | 8 | ASCII `"UsbTask"` |
| 0xC01F9C38 | 0x2A50 | TI SYS/BIOS 内核错误字符串表(见下) |
| 0xC01FC6A0 | 0x1760 | 代码形态 |
| 0xC01FF654 | 0xBC | 指向 0xC01Dxxxx 的指针表 |
| 0xC01FF800 | 0x200 | 结构/配置(前部清零) |
| 0xC02002BC | 0x670 | 代码/数据 |

**结论性判读**:链 B = 设备进入固件更新待机(开机按住 Up+Down)时运行的
**更新模式固件**(USB 通信任务),与日常 OS(链 A)分离。0xC01F9C38 的
字符串明确是 **TI SYS/BIOS(DSP/BIOS)** 内核断言文本(`HeapStd_create`、
`A_badThreadType`、`BIOS.clockEnabled`、`Swi/Hwi/Task` 等)→
**固件 DSP 侧跑 TI-RTOS(SYS/BIOS)**;`UsbTask` 即其一个 Task。
(此前文档未识别 RTOS 层。)

导出:每个记录按 `c<addr>_<len>.bin` 存于 `firmware/g1on_v121/os_chunks/`
(含 `records.json` 清单 + SHA1);同时复制为 `analysis/b1on_os/chunk_*.bin`
供生成器使用。

### 7.1 破墙方法(本轮核心工程成果)

上一轮卡死的根因在本轮被逐一定位并修复(见 §4):
数据表/伪指令区没有构造器 → 反编译器顺流走进去即报
`Unable to resolve constructor` 并卡死。修复分三层:
① 4,857 个 `.word` 数据字补 NOP 构造器;
② 4,336(+9,230 个 +2 错位窗口)个未覆盖位置补 `return [B3]` 终止构造器;
③ 每个填充点再补 +2 错位窗口(反编译器按最长匹配推进会落在数据字的
+2 偏移上,实测 c0085f5e 等五处均为该形态)。
修复后 30/30 全部反编译成功,残余 Warning 不再中断输出。

### 7.2 反向确认的运行时结构(逐条与新反编译对照)

| 结构 | 反编译证据 |
|---|---|
| 每槽处理器表 `0xC00DD528[slot]` ← 48B 记录 **+8 (word8)** | `f_c00beac0`: `*(iVar3 + 0xd528) = *(iVar2 + 8)`(iVar2 = c008940c 读记录) |
| 默认处理器 `0xC00C6840`,五槽初始化 | `f_c00bea38`: 循环 5 次写 `0xd528` 槽表,初值 `0x6840` |
| 每槽链位记录表 `0x1180B160 + slot*0x2c + idx*4` | `f_c0098b98` 开头 `(iVar5 + 0xb160 + param_2*4)`;`f_c0098ad8`: `pcVar18 = *(code **)(slot*0x2c + 0xb160 + idx*4)` ——**链位间接调用点**(文档所述 B.S2X 的目标来源) |
| 每槽位图 `0x1180B23C` | `f_c0098b98` 读 `puRam0000b23c`、`0xb161` 字节 |
| 每槽标志字节 `0xC00DD728` | `f_c00939c4`: `*(slot + 0xd728) = 0xff`;多处 `1 << idx` 位操作 |
| 5×640KB 外部缓冲启动清零 | `f_c00bd2a4`: 五次 `(ptr, 0, len)` memset,指针低 16 位 `5800/1c40/e080/a4c0` 与文档的 `0xC01A5800/0xC0251C40/0xC02FE080/0xC03AA4C0…` 逐一吻合 |
| 每槽 ctx 表 `0xC00DD4F8` | `f_c00b6fe8`/`f_c00b7208`(DLY/REV 激活函数)开头即引用并返回该表 |
| 双区标志清零 `0x117FF000/0x117FF400 + slot*0x400` | `f_c00939c4`、`f_c007d768` 写 `+0xf001/+0xf401` |

### 7.4 大区缓冲链的完整静态证据(2026-10-13 补充)

缓冲区机制已从原始反汇编逐条打通(不再依赖推断):

1. **静态描述表实体就在固件里**:`0xC00DF948` 处数据 = 5×{基址, 0xAC440}:
   `{0xC01A5800,0xAC440} {0xC0251C40,0xAC440} {0xC02FE080,0xAC440}
   {0xC03AA4C0,0xAC440} {0xC0456900,0xAC440}`,尾部哨兵
   `{0xC0456900, 0xC0502D40}`(=区域基址/上界)。与文档早前推断**逐字节吻合**。
2. **清零函数 `c00bd2a4` 全文解出**(原始反汇编):五次
   `memset(base_k, 0, 0xAC440)`(槽距=0xAC440 = 0xA0000 可用 + 0xC440 保护带;
   反编译器曾把长度折叠成乱值,从 `MVK 0xFFFFC440`+`MVKH 0xA0000` 的
   延迟槽配对复原)+ `memset(0xC0502D40,0,…)` + `memset(0x11800000,0,0x7800)`。
3. **运行期数组**:`0xC00DD558[k]`=缓冲基址、`0xC00DD540[k]`=长度(各5项),
   小型访问器在 `c00bd260`/`c00bd26c`;`c00bd350` 函数用这两张数组循环
   重新清零。访问器无直接 CALLP 调用点(经指针间接调用,与 word7 调度
   体系一致)。

**唯一剩余环节**:把某个槽的 ctx[3] 指向大缓冲的那条按 real_type 判定的
分支,尚未在合并膨胀的输出中逐指令钉死——实机探针(§9)是最终判据,
拿到设备后随时可做。

### 7.6 跨平台对照(MS-70CDR 既有硬件验证 vs 本机发现)

把 `third_party/ZoomMultistompZDL`(MS 平台构建链,硬件验证过的 ABI 文档)
与本轮发现对照,得到关键跨平台结论:

- **MS-70CDR 给自定义效果的 ctx[3] 默认 ≈ 705,536B**(硬件探针
  DescSize/Dsz689K),与 B1on/G1on 的槽缓冲 0xAC440(705,600B)同量级、
  结构同源(base/end/span 描述符 + 大缓冲池)。**但 B1on/G1on 自定义
  效果只拿到 1KB** —— 这是**平台差异**,不是 ZDL 字段问题。
- MS 文档确认 **SONAME 前缀与类别(gid/real_type)不匹配 → 固件回退
  "无分页 2 旋钮"渲染** —— 与实机"无 UI"症状完全对应,列为自制 ZDL
  首查项。
- MS 文档硬件验证的冻结点:`.fardata` 过大 / `memsz≠filesz` /
  缺 `--mem_model:data=far` / 借用手柄缺 `state[7]` 尾调用(UI postbox)。
- 汇总成上线自检单:`docs/CUSTOM_ZDL_COMPAT_CHECKLIST.md`。

### 7.3 剩余缺口(需要实机)

"槽激活时 ctx[3] 指向 1KB 槽区还是 640KB 大缓冲"的**决定性字段**仍未
静态钉死(候选:w28 / real_type;w28 已证明只进预算检查)。上一轮已构建
好只读探针,本轮结论不改变其判读,步骤见 §9。

已知且已接受的残余 Warning(不再中断输出):

- `Unable to resolve constructor at c00a4ade`:唯一仍无构造器的错位落点
  (真实指令的 +2 偏移,不在 +2 窗口覆盖的填充类里);不影响任何函数完成。
- `Unable to read bytes at ram:0000df30 / ram:0000df98`:反编译器把数据区
  某值当地址读(历史已知项),以警告形式保留。
- 大函数输出存在 call→branch 合并膨胀(单函数 100KB+):**真实函数体在
  文件开头**,合并尾段为反编译器流探索伪影;已验证与 CALLP 语义无关
  (改语义试验零差异,已回滚)。读解时只看头部。
